# WHENCALENDAR — 프로젝트 정의

> 몰입 중 시간 인지를 푸는 트레이 상주 캘린더. 형제 앱 [WHENWORK](https://github.com/when630/whenwork)·[WHENNOTE](https://github.com/when630/whennote)·[WHENMAIL](https://github.com/when630/whenmail)과 같은 스택·구조·배포 방식을 쓰고, 역할만 나눈다. 요구사항 ID는 [02_요구사항.md](02_요구사항.md), 기술 결정은 [03_기술_스펙.md](03_기술_스펙.md). 2026-09-17 v0.1.

## What This Is

WHENCALENDAR는 **알림을 울리지 않는 캘린더**다. 화면 위쪽에 작은 아일랜드가 상주하면서, 다음 일정이 가까워질수록 스스로 커진다. 창을 여는 일은 드물다 — 일정은 `.ics` 구독으로 알아서 들어오고, 직접 등록할 때만 창이 필요하다.

이 앱은 WHENWORK가 **스스로 도려낸 자리**를 물려받는다. WHENWORK는 공개판 전환에서 캘린더 연동과 오늘 뷰의 일정 타임라인을 제거했고(`whenwork/docs/03_요구사항.md` RMV-03), 표준 OAuth 연동은 서명·검증 비용 때문에 Out of Scope로 남겼다(`02_공개판_프로젝트.md`). 빈 땅에서 시작하는 것이 아니라, 잘려나간 기능이 제 몫의 앱으로 돌아오는 것이다.

## Core Value

**몰입해도 시간을 잃지 않는다. 창을 열지 않아도, 보려고 하지 않아도, 다음 하나까지 얼마 남았는지 안다.**

기존 도구가 이걸 못 푸는 이유는 한 문장으로 요약된다 — **알림은 "시점"이고, 몰입 중에 필요한 건 "상태"다.**

- 캘린더의 10분 전 팝업은 **한 번** 울리고 끝난다. 몰입한 사람은 그 한 번을 놓친다. 그리고 10분 전은 이미 늦다 — 하던 것을 정리할 시간이 없다
- 시계와 트레이 아이콘은 **봐야** 보인다. 몰입하면 보지 않는다. 시계가 있는데도 시간을 잃는 이유가 이것이다

그래서 이 앱은 시점에 한 번 알리는 대신 **연속된 상태**를 화면 가장자리에 둔다. 60분 넘게 남으면 점 하나, 30분부터 펼쳐지고, 5분부터 붉어지고, 1분에 숨을 쉰다. 어느 단계에서도 클릭을 요구하지 않고 포커스를 뺏지 않는다.

## 설계 원칙 — WHENWORK와 대칭

| | WHENWORK | WHENCALENDAR |
|---|---|---|
| 제1원칙 | **입력 비용 최소화** — 하루에 수십 번 던지니까 | **조회 비용 0** — 일정은 하루 두세 개지만 "지금 몇 시지, 다음 뭐지"는 하루 수십 번 확인한다 |
| 주 UI | 창 (열어서 본다) | 트레이·오버레이 (열지 않는다) |

이 대칭이 두 앱을 합칠 수 없는 이유이기도 하다. 한쪽은 창을 여는 앱이고 한쪽은 창이 없는 앱이라 UI 모델이 정반대다.

## 페르소나

| | 특성 | 도출되는 요구 |
|---|---|---|
| 주 사용자 | 한국어 사용, Windows 11 · macOS(2026-09-19부터 둘 다 낸다), 코드·문서에 한 번에 한두 시간씩 몰입한다. WHENWORK·WHENNOTE 사용자와 같은 사람 | 네 앱의 단축키가 충돌하지 않아야 함. 같은 팔레트·같은 키 관습 |
| 상황 | 전체화면 IDE, 화상회의, 몰입 중 | **전체화면 앱 위에** 떠야 함. 포커스를 뺏지 않아야 함. 클릭이 통과해야 함 |
| 상황 | 회의가 예정보다 길어지는데 다음이 붙어 있다 | 다가오는 일정뿐 아니라 **진행 중인 일정의 종료**도 알려야 함 |
| 태도 | 일정을 손으로 옮겨 적지 않는다. 내 일정의 대부분은 남이 회사 캘린더에 잡는다 | `.ics` 구독이 v1 필수. 손 입력만으로 채워야 하는 캘린더는 2주 만에 죽는다 |
| 태도 | 몰입 중에 숫자를 읽을 여유가 없다 | 색과 두께로 먼저 말하고, 글자는 가까워졌을 때만 |

## 스코프

### 포함 (v1)

- **상단 아일랜드 오버레이** — 링 게이지로 남은 양, 남은 일정 점, 진행 중·종료 임박 구분, 마우스 호버로 즉시 펼침
- **점진적 침범** — 60분 이상 점만 → 30분부터 펼침 → 10분 완전 → 5분 발광 → 1분 맥동. 단계마다 클릭·포커스 요구 없음
- **`.ics` 구독** (읽기 전용, OAuth 없음) + 이 PC에 직접 등록
- **본체 창** — 오늘 · 주 · 월 · 구독 · 설정. 키보드만으로 끝까지
- **빈 시간 찾기** · **가능 시간 복사**(클립보드까지만) · **검색**(지난 일정 포함, 초성)
- 내장 저장소 단일 파일, JSON 내보내기·가져오기
- Windows 설치 파일, GitHub Releases 미서명 배포, 자동 업데이트 알림

### 제외

| 기능 | 이유 |
|---|---|
| 할 일·체크박스·완료·마감 | WHENWORK의 역할. 일정은 "완료"되지 않고 **지나간다** |
| **타임블로킹** (할 일을 캘린더로 끌어다 놓기) | 가장 유혹적이고 가장 위험하다. 이걸 넣는 순간 WHENWORK를 통째로 삼킨다 (2026-09-17 결정) |
| 긴 메모·마크다운 에디터·태그·백링크 | WHENNOTE의 역할. 일정 설명은 한 줄이다 |
| 참석자·연락처·후속 리마인더·초대 메일 | WHENMAIL이 이미 사람과 회신 대기를 다룬다 |
| 시간 추적·회고 일지 ("실제로 뭘 했나") | WHENWORK 실사용에서 **"이미 끝난 일의 이중 장부 정리라 아무도 하지 않는다"**가 증명됐다 (`whenwork/docs/01_설계.md` 12.11) |
| OAuth 캘린더 연동 (Google·Microsoft API) | 앱 심사·서명·검증 비용이 "설치 파일 하나"에 어긋난다. **비공개 `.ics` 주소 구독**으로 같은 값을 얻는다 (WHENWORK Out of Scope 승계) |
| 캘린더 쓰기(구독한 달력에 일정 추가·수정) | 읽기 전용 구독이라 원리적으로 불가. 직접 등록은 이 PC 저장소에만 |
| 클라우드 동기화·계정 | 1인 1PC. 내보내기·가져오기가 이동을 대신한다 (형제 앱 동일) |
| AI 자연어 해석 (LLM 호출) | 구독·API 키 전제가 "설치 파일 하나"에 어긋난다. v1의 한 줄 입력은 **규칙 기반 로컬 파서**로만 (v2 후보, [03 §자연어](03_기술_스펙.md)) |
| 협업·공유·권한 | 원 설계 전면 배제 |

## 형제 앱과의 경계

| 앱 | 답하는 질문 | 핵심 명사 |
|---|---|---|
| WHENWORK | 뭘 해야 하지 · 뭐가 밀렸지 · 누굴 기다리지 | 할 일 — 내가 옮길 수 있고, 마감만 있다 |
| WHENNOTE | 그때 뭐라고 적었더라 | 메모 — 시간과 무관하다 |
| WHENMAIL | 이 사람한테 마지막으로 언제 연락했지 | 사람 |
| **WHENCALENDAR** | **다음 하나까지 몇 분 남았지 · 이번 주 어디가 비지** | **시각 — 남이 정했고 내가 못 옮긴다** |

할 일과 일정을 가르는 선은 중요도나 체크박스 유무가 아니라 **내가 옮길 수 있느냐**다. 할 일은 미루면 미뤄지고, 비행기는 안 기다린다. 그래서 일정에만 충돌·점유·반복·초대라는 문제가 생기고, 그것이 WHENWORK가 구조적으로 못 다루는 영역이다.

### 겹칠 위험이 있는 세 지점

| 지점 | 처리 |
|---|---|
| WHENWORK 아침 브리핑의 "일정" 줄 | RMV-03으로 타임라인은 지웠는데 브리핑 항목은 남아 있다(`whenwork/docs/01_설계.md` §브리핑). **WHENCALENDAR가 서면 그 줄은 WHENWORK에서 빠져야** 두 앱이 아침에 같은 말을 두 번 하지 않는다 → [오픈이슈 #1](03_기술_스펙.md#오픈이슈) |
| 알림 층위 | WHENWORK는 하루 1회 마감 브리핑, WHENCALENDAR는 실시간 연속 상태. 층위가 다르지만 사용자에겐 둘 다 그냥 알림이다 |
| 전역 단축키 | WHENWORK `Ctrl+Alt+Space`, WHENNOTE `Ctrl+Alt+M`·`Ctrl+Alt+N`. WHENCALENDAR는 `Ctrl+Alt+C`(창) → [오픈이슈 #2](03_기술_스펙.md#오픈이슈) |

네 앱은 코드를 공유하지 않는다(모노레포·공용 패키지 없음). 검증된 모듈을 복사해 시작하고 각자 진화한다. 공유하는 것은 **스택·모듈 구조·디자인 토큰·빌드/릴리스 파이프라인·테스트 방식**이다.

## 완료 판정

작성자가 2주 사용한 뒤 **"몰입하다 일정을 놓치거나 늦은 날"이 0일**이면 v1 완료.
